## SoA and WebGPU migration (NGNE-27)

The platformer moved from the object-component bridge and the previous renderer to schema components and the WebGPU renderer without engine changes. Simulation is unchanged: the walkthrough's canonical state hash matches the pre-migration capture at every tick (see [verification](../../docs/verification.md#ngne-27--13-september-2026)). Friction found; items 10–14 are expressible with supported API, and item 15 is an open engine API decision:

## Authored-level walkthrough

The deterministic reference walkthrough in [tests/platformer.test.ts](../../tests/platformer.test.ts) completes `LEVEL_ONE` then `LEVEL_TWO` in **1,448 ticks with zero deaths**, ending on the completion overlay with `completed: [true, true]`. A second independent run produces identical final `enumerate()` output.

The command sequence is exactly: checkpoint 1, exit, checkpoint 1, checkpoint 2, exit. The test asserts that sequence, zero deaths and completion within 4,000 ticks.

The test-only driver reads enumerated player/patrol poses and authored tile data each tick, holds right, and starts a 24-tick jump hold when grounded near a gap (6 px), spike (22 px) or patrol (36 px). It distinguishes safe drops to lower support from bottomless gaps. No randomness, wall-clock decisions, level edits or controller tuning were needed. This proves a deterministic completing route; it does not establish browser controls, audio playback or difficulty for human players.
