# Frozen CI baseline procedure

The [baseline record](ci-cost-baseline.json) is explicitly incomplete. Empty measurements are not zero-cost runs, a denominator or budget compliance. Hosted execution and consumer agreement are separate gates.

The local draft [ci-baseline.workflow.yml](ci-baseline.workflow.yml) retains the frozen verification steps, uses an exact frozen checkout, disables deployment by removing both showcase publication and the deploy job, and allows only manual dispatch. It is intentionally outside `.github/workflows`; it cannot run automatically. Original workflow bytes and their SHA-256 remain fixed in the baseline record. The draft adds a 30-minute hang guard and environment logging; all original verification commands and failure-injection checks remain. Setup-node retains the original Node 24/npm-cache configuration. The original consumer coverage is retained because this is the old baseline.

After authorization and authenticated dispatch access:

1. Publish only this reviewed draft as a uniquely named workflow on a non-main measurement branch. Verify dispatch availability for that branch; GitHub may require the dispatch workflow to exist on the default branch, in which case obtain approval for a separate deployment-disabled workflow-only change. Do not dispatch the original workflow on main. Never change the measurement checkout to current implementation HEAD.
2. Record the measurement branch revision and workflow hash, verifying the checkout pin, frozen Git blob hash and absence of deploy/pages-upload jobs. Launch five deliberate successful runs sequentially; record every failed attempt too. Do not replace a slow successful run. If the 30-minute guard proves insufficient, record the explicit adjustment and retain failed attempts.
3. Fetch run/job metadata and every step timestamp (excluding queue time), setup-node cache-hit logs, runner-image/version and Node/npm/Chrome versions from logs. Record actual cache state for every run; matching final runs must reproduce the condition sequence. Do not label the first run cold without evidence of a cache miss. Retain the baseline's original verification artifact upload, record each artifact's ID/name/size and total uploaded bytes through the Actions API. Preserve failure artifacts.
4. Fill successfulRuns/failedAttempts using the required fields in the record. Stage entries include name, conclusion, start/end and absolute seconds. Artifact entries include ID/name/bytes. Store raw API/log provenance beside the recorded timings. Compute the median only once five successful measurements exist. Do not infer zero seconds for missing timestamps.
5. Final acceptance needs five matched runs, a required-coverage old-to-new stage map, absolute stage/wall durations and artifact sizes, and median growth at most the proposed 20%. Rebaseline if environment/cache drift prevents matching. Consumer removal is a scope change, not an engine speedup; record explicit compatibility cost separately.

The current session can inspect a restricted slice of hosted history but cannot dispatch through its exposed GitHub tools; no `gh` executable is available. No hosted run, publication, deployment or baseline timing is claimed. Baseline-dependent delivery/cost acceptance remains blocked until this procedure is executed.
