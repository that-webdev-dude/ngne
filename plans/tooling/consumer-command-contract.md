```text
npm run verify:engine -- --contract-version 1 --engine-tarball <absolute-path> --engine-sha256 <sha256> --output <new-absolute-run-directory> --run-id <id>
```

The caller selects a consumer checkout or pinned artifact explicitly, records its revision and source/lock SHA-256 inventories before execution, and runs this command from that checkout. No default consumer, sibling discovery, engine-internal prepared manifest, or shared-workspace installation is permitted. The caller owns command termination; the consumer owns isolated installation, scenarios, child processes and cleanup. The consumer documents its dependency/browser prerequisites and verifies tarball bytes before installing.

- Reject unsupported versions, invalid arguments, hash mismatch and existing output before installation. Exit 2; never overwrite old output. Invocation flags are required exactly once; unknown flags fail.
- After exclusive output allocation, persist partial result evidence before work. Preserve execution, assertion, diagnostic, cleanup and publication failures. Final acceptance follows cleanup and evidence publication. Exit 1 for unsuccessful execution or publication; partial/missing evidence never passes validation.
- Exit 0 only for accepted complete evidence with at least one required stage. Exit 1 may return a valid complete failed response. Exit 2 is always a failed compatibility invocation, even if an unrelated old response exists.

Write `output/evidence/{manifest.json,result.json,artifacts.json,report.md}`. Preserve the exact tarball at `evidence/package/<actual-filename>.tgz`. All paths inside evidence are relative POSIX paths; reject traversal, absolute paths and linked payloads. Inventory every evidence file except `artifacts.json` itself with SHA-256 and byte length. Publish inventory after final records/report; missing or extra files invalidate it.

The manifest discriminator is `consumer-manifest`; engine preparation continues to use `manifest`. Both use the common `ngne-tooling` v1 header and shared result/artifact validators. The consumer manifest requires contractVersion 1, selected package filename/path/hash, nonempty installed-engine inventory, consumer revision/source/lock inventories, and observed Node/platform/release/architecture. See the [schema example](../../tooling/tests/fixtures/consumer-contract-v1/successful-response/evidence/manifest.json) and [result example](../../tooling/tests/fixtures/consumer-contract-v1/successful-response/evidence/result.json). Inventories hash file bytes with stable relative keys. Installed identities are consumer-reported observations; the protocol cannot independently prove an installation or a truthful assertion. Real conformance must exercise installation and consumer-owned checks.

`result.json` uses the existing independent execution/correctness/budgets/cleanup/evidence dimensions, stages, failures, cleanupRecords and accepted field from [schema.ts](../../tooling/evidence/schema.ts). At least one stage must be required. Complete failed records retain their failures. Stage observation/measurement documents use their matching discriminator and the same child run ID. A parent aggregate records that child ID separately.

Every invocation, including nonzero exits, must call [validateConsumerResponse](../../tooling/evidence/consumer-contract-v1.ts). Supply the caller's preselected run ID, package filename/hash and consumer revision/source/lock inventories; do not derive expected identities from the response. Preserve original exit/failure diagnostics alongside validation exceptions. The validator checks document types/versions, required fields, identities, terminal outcomes, exit consistency, inventory membership, hashes, sizes and physical containment.

Record caller revision plus `consumerValidatorIdentity(repository)` in compatibility evidence. Its SHA-256 inventory includes the validator, shared schema and identity implementation plus every conformance fixture. This avoids a self-referential pinned source hash. Breaking changes require an explicitly selected new contract version; never fall back silently.
