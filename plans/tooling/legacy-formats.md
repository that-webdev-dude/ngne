# Bounded legacy formats

These synthetic fixtures freeze the existing readers' semantics; they are not measurements or historical run conversions. Select the family explicitly through [legacyFormat](../../tooling/evidence/legacy-format.ts), then use the existing reader. This selector does not replace payload validation or grant comparison acceptance. Future extracted readers must preserve these gates. Existing legacy CLIs remain unchanged during migration.

| Family / named fixture                         | Files and expected behavior                                                                                                                                                                                                |
| ---------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| content-legacy / content-valid                 | Untagged manifest, fixtures, runs, result. Existing strict comparator accepts matching policy/OS/package/installed/build/source/harness/tooling/fixtures/environment/visibility and passed result with successful cleanup. |
| content-legacy / content-cleanup-failed        | Same data with failed cleanup; comparator exit 2.                                                                                                                                                                          |
| content-legacy / content-missing-tooling       | Missing recorded tooling identity; comparator exit 2. Unknown identity is never invented.                                                                                                                                  |
| benchmark-legacy / benchmark-per-stage         | Schema 1 manifest plus churn/result.json; existing loadRun per-stage path.                                                                                                                                                 |
| benchmark-legacy / benchmark-consolidated      | Schema 2 manifest, analysis schema 1, retained per-stage result; provenance and result digest validation.                                                                                                                  |
| benchmark-legacy / benchmark-compact           | Same consolidated analysis with compact retention and no stage files; identical metrics.                                                                                                                                   |
| benchmark-legacy / benchmark-missing-analysis  | Schema 2 without analysis; reject Missing consolidated analysis.                                                                                                                                                           |
| benchmark-legacy / benchmark-tampered-analysis | Incorrect embedded result hash; reject Analysis mismatch.                                                                                                                                                                  |
| unsupported.json                               | Unknown schema/family, curated summary and new-format evidence; explicit Unsupported legacy format error.                                                                                                                  |

All fixtures live under [tooling/tests/fixtures/legacy](../../tooling/tests/fixtures/legacy). [Tests](../../tooling/tests/legacy-formats.test.ts) execute the existing content comparator and aggregate reader/comparator, preserving default attentionPercent 10, metrics and schema-difference compatibility warnings. Existing benchmark-output tests additionally cover scan precedence and regression/improvement directions. These legacy readers do not promise candidate comparison. A schema 1 versus schema 2 scan may show identical metrics while reporting CHECK COMPARABILITY; advisory CLI exit zero is not acceptance.

Exactly two reader families are supported. New-format/mixed comparisons require remeasurement, not invented historical run IDs. Curated installed-content, runner-cleanup and content summary JSON/Markdown/archives remain original historical evidence with **zero conversion adapters**. No historical artifact or old runner is removed.
